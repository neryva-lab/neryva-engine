# Control Plane — Implementation Plan

**Workstream:** the `/console/**` APIs behind the web app's `/platform` area: product manifests, console home with product cards, summary providers, and contract ownership.
**Binding docs:** [`console/product-integration.md`](../../../architecture/console/product-integration.md) (the contract, incl. the contract-composition rule), [`console/overview.md`](../../../architecture/console/overview.md), [ADR-004](../../../architecture/decisions/ADR-004-frontend-portal-corporate.md).
**Depends on:** organizations (entitlement states, projects), partitioning (route/manifest enforcement).

## Current state (verified)

- Admin routes exist per concern (`backend/app/api/routes/{policies,usage,sessions,threads,…}.py`) authenticating via API keys/operator sessions — but there is **no console-home, no product registry, no summary framework, no contract ownership tags**.
- The pinned contract: `contracts/openapi/openapi.v1.json` (103 paths), regenerated by `backend/scripts/export_openapi.py`; CI fails on drift.

## Target

A product-manifest registry the console shell renders from; `GET /console/home` resolving cards (manifest + entitlement state + cached summaries); the summary-provider schema as a CI-tested contract; `x-neryva-owner` on every contract path with a bijection check.

## Steps

**C-1 — Manifest registry (no schema change first).** `backend/app/gateway/catalog.py` already demonstrates registry patterns; add `backend/app/platform/manifests.py`: manifests as **versioned Python/YAML artifacts in-repo** (`backend/app/products_manifests/*.yaml`), loaded at startup into an in-memory registry (key, version, faces, console nav, scopes, entitlement codes, summary route, metering tag, runtime routes). A `products` table is unnecessary until manifests need runtime editing — YAGNI, Rule of Two. *Gate:* registry loads; unknown-key 404s.

**C-2 — Contract composition.** Extend `export_openapi.py`: every path gains `x-neryva-owner` (initial split: `platform` for org/identity/usage/governance paths, `agent_studio` for conversations/threads/openai-compat/surfaces — the existing 103 paths get tagged in this step); the script **fails** on any route not owned by a registered manifest key or any manifest route missing from the spec. CI gets the bijection check (contract pin step already exists — extend it). *Gate:* re-pinned contract carries owners; CI red on a deliberately unowned test route.

**C-3 — Summary-provider contract + fake product.** Define the card schema (product, status, kpis[{label,value,delta}], alerts, primary_cta) as a Pydantic model; `GET /console/home` gathers per-registry-product: entitlement state (organizations O-2) + summary (call the manifest's summary route in-process, cache `cache_seconds`, empty-kpis fallback for no-data products). CI test: a fake product manifest with a stub provider renders a card — the contract cannot silently drift. *Gate:* home endpoint integration test (owned/trial/none/past_due states per access-model).

**C-4 — Org furniture APIs mount under `/console/org/**`** (delivered by organizations O-4; this step wires them into the home payload + nav model so the web app renders one coherent shell). *Gate:* contract re-pin; nav/home payload snapshot test.

## Files touched

`backend/app/platform/{manifests.py,console_home.py}` (new), `backend/app/products_manifests/{agent_studio.yaml,deployment.yaml}` (agent-studio real; deployment registered only when its module lands), `backend/scripts/export_openapi.py`, `.github/workflows/ci.yml` (bijection check), `backend/tests/test_console_{home,manifests,contract_owners}.py`, contract re-pin.

## Rollback

C-1/C-3 are additive routes behind L1; C-2 is tooling (worst case: owner tags dropped, contract unchanged in shape). No existing path changes semantics.
